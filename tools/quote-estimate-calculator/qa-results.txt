Decisions this run locked in (documented in the page's own help text):
- Blank rows: a line counts only with qty > 0 AND a parsed unit price; otherwise the
  line total renders empty, never $0.00. A unit price of 0 IS a real line.
- Negative / non-numeric qty or price: the line is ignored entirely (contributes 0),
  the row border turns red. Negatives are never silently clamped into the subtotal.
- Discount: percent capped at 100%, flat capped at the subtotal, so the total can
  never go below $0.00. Tax is charged on the subtotal AFTER the discount.
- Rounding: half a cent up at every step. The (n + Number.EPSILON) trick used by the
  older tools is NOT sufficient - 2.5 x 19.99 = 49.974999999999994 and the nudge
  returns 49.97. This page trims to 12 significant digits first, giving 49.98,
  3 x 0.145 = 0.44 and 1 x 0.615 = 0.62. That bug was found by this QA run.
